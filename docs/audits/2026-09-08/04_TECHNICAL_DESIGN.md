# 04 — Technical design (2026-09-08)

How to close the seven roots and one dependent in `02_DEVIATIONS.md`. Every figure here is the one
`02` and `03` carry; the two documents are read as one.

**Nothing in this bundle touches addon behavior.** Five of the eight edits are comment or prose
text, two are one config line each, and one is a test-file change. No `.lua` that ships changes
what it does; `modules/`, `defaults/` and `locales/` are not opened at all.

## WG-54 — two British spellings

**Files:** `core/WhatGroup.lua` only.

Two words in two comments, no identifier and no string:

| Line | Now | After |
|---|---|---|
| `:60` | `…two varargs travelled into handler bodies…` | `…two varargs traveled into handler bodies…` |
| `:779` | `…the emptiness is the behaviour:…` | `…the emptiness is the behavior:…` |

**Do not touch the three `cancelled` sites** — `core/WhatGroup.lua:740`, `docs/data-flow.md:56`,
`tests/test_capture.lua:433`. They are `C_LFGList`'s own application-status token and
`localization-§5`'s *Blizzard and third-party symbols* exception requires them verbatim; "fixing"
`APPLICATION_ENDED.cancelled` breaks the dispatch at `core/WhatGroup.lua:776`. This is the trap in
this item, and it is why the sweep is done with the published `ALLOWED`-first algorithm rather than
a bare `grep -i`.

**The durable half.** `localization-§5` now publishes `BRITISH` and `ALLOWED` and MUSTs that any
mechanical gate carry **both, whole**. This repo has no such gate — which is exactly why `M4-13`'s
sweep held for a few hours and then two new hits landed in the same file on the same day. Add
`tests/test_prose.lua`:

- copy both lists **verbatim** from `localization-§5`, with a comment saying they are copied and
  that a new entry lands upstream first;
- remove `ALLOWED` as **delimited whole words** before scanning, not as substrings — otherwise
  *analysed* hides inside the allowance for *analyses*;
- name the four exclusions **file by file / directory by directory** in the test, as §5 requires,
  so the list cannot quietly grow: `libs/`, `tests/_kit/`, the frozen bundle directories, and this
  test's own copy of the lists;
- **the case's own file must be excluded**, or it reddens on itself.

Risk: the gate is only as good as its exclusion list, and `localization-§5` warns that the four
words deliberately left out (*towards*, *afterwards*, *forwards*, *learned*) must stay out.

## WG-62 — ten unresolvable standards citations

Two independent edits, one sweep each. Neither changes behavior.

**(a) `lint-§1` → `lint`, 8 sites.** `documentation-§6` names eleven section files that carry no
numbered subsections and are cited by **bare filename**; `lint` is one. Each site drops `-§1` and
keeps everything else:

`.luacheckrc:13`, `:19`, `:73`; `docs/testing.md:299`; `tests/test_lintconfig.lua:1`, `:131`,
`:151`, `:262`.

Two of those are inside **assertion message strings** (`tests/test_lintconfig.lua:131`, `:151`),
so the edit is visible to a reader of a failure and nothing else; one is a **file header** (`:1`).
None is matched on, so no case changes result.

**(b) `code-quality-§3` → `performance-§10`, 2 sites.** `core/WhatGroup.lua:744` and
`docs/module-map.md:17`. There has never been a `code-quality.md`; the rule both comments mean is
the CCN ceiling, which lives in `performance-§10` and is enforced at `automated-tests-§3`'s release
gate. `docs/module-map.md:17` is a single very long table cell — edit the token in place; do not
reflow the row.

**The durable half, and it is cheap.** The range-check is one `grep -c '^### [0-9]'` per cited
section file, exactly as `documentation-§6` specifies, and it is the check that would have caught
all ten on the day they were written. It belongs in `tests/test_doc_structure.lua`, but it needs
the standard's section files, which the headless suite cannot fetch. Two honest options:

1. **A committed section-index** — a small table of `<section> → <numbered subsection count>`
   checked into `tests/`, regenerated by `/wow-addon:revendor-standards`. Cheap, and stale between
   regenerations, which is the failure mode this whole finding is an instance of.
2. **The eleven bare-filename names only** — hard-code the eleven `documentation-§6` names and
   assert no `filename-§N` cites any of them, plus assert that every cited `filename` is in the
   26-name Sections list. That catches both of today's forms and needs no counts, so it cannot go
   stale in the dangerous direction.

**Option 2 is the recommendation.** It is a list of names, both halves of it are in
`documentation-§6`'s own prose rather than derived, and it fails closed: a section renamed upstream
turns the case red rather than green.

## WG-63 — the gate that let WG-61 through (`derived from WG-61`)

**File:** `tests/test_register.lua`. Two changes, both to what the case *looks at*, neither to what
it asserts.

1. **Stop excluding review ids** (`:94`). `not id:find("%-R%-")` was defensible before v2.39.0's
   third MUST; that MUST names three id kinds and a review finding id is one of them. Resolve a
   review id against `docs/reviews/*/*.md` with the same `isAssigned` predicate, against a second
   corpus.
2. **Stop counting a bundle's register echo as an assignment** (`:59-77`). `isAssigned` accepts an
   id heading any table cell in any bundle file. Every audit bundle since 2026-08-05 reproduces the
   register in a *Recorded deviations* table, so a dead id is "assigned" by the very document that
   quotes it. Narrow the corpus: skip any table row inside a `## Recorded deviations` section
   (slice the bundle the way the case already slices `ARCHITECTURE.md`), or — simpler and stricter —
   accept an id only where it heads a `### ` **heading**, which is where every bundle actually
   assigns one.

The second option is the recommendation: it is one predicate instead of two, it is what the file's
own comment at `:38-42` is already reaching for, and `docs/audits/2026-08-05/02_DEVIATIONS.md:113`
(`### WG-37 — …`) confirms the heading form is what a bundle uses to assign.

**Falsifiability is the point** (`testing-§12`): after the change, restoring either dead id to the
register must turn the case **red**. Verify that by hand before committing — a gate for this MUST
that cannot fail is the failure mode the MUST exists to catch, one level up.

## WG-48 — the record is three commits behind HEAD

**Not a code change, and not a commit gate.** `automated-tests`' checkpoint is **release**. The
design is a process one: `tests/_kit/run-automated-tests.sh` runs as part of cutting the tag, after
the last commit, not before it. Today's numbers (`03` §G) show the drift is size only — NLOC
7702→7913, functions 1044→1050, `luacheck` files 40→41, cases 554→559, with max CCN unchanged at 15
and nothing entering the band — so re-running today would produce a green record with no new watch
list row and no new disposition.

There is nothing to fix in this repo's files. If a run is taken now, it must be taken **from HEAD**
and its `ANALYSIS.md` written into its own bundle; the two older bundles that carry none stay as
they are, because `automated-tests-§5` now **MUST NOT** backfill.

## WG-51 — the vendored gate does not assert `100755`

**Not fixable here.** `testing-§1` forbids editing `tests/_kit/`, and a local patch would be
reverted by the next re-vendor. The change belongs in `LibKa0s`'s `testkit/vendor_sync.lua`:

```lua
-- automated-tests-§2: the one payload property the working tree cannot answer.
-- DrvFs reports every file rwxrwxrwx and core.fileMode=false makes git ignore the tree,
-- so both signals a reader would trust are silent. Ask the INDEX.
local mode = capture("git ls-files -s tests/_kit/run-automated-tests.sh"):match("^(%d+)")
assertEqual(mode, "100755", "run-automated-tests.sh must be recorded executable; fix with "
  .. "git update-index --chmod=+x tests/_kit/run-automated-tests.sh")
```

It arrives here on the next re-vendor and bumps the kit revision past 15. **This repo's mode is
already correct** (`git ls-files -s` → `100755`), so nothing is broken meanwhile; what is missing is
the guard against the day a `cp`-based re-vendor drops the bit.

Raise it on `LibKa0s` with a pointer to `automated-tests-§2`'s own sentence — *"Nine identical
failures against an explicit MUST is what a rule with no test looks like"* — and note that
`M1-LK-07` closed this item's sibling (the manifest `skipped` key) and not this half.

## WG-56 — `Tab | Covers` versus page granularity

**Upstream only; nothing changes here.** `documentation-§1` item 7 names the table
*"a **Tab | Covers** table"* and in the same sentence mandates *"one row per settings subcategory…
stays at page granularity"*. The two cannot both be satisfied, and this repo picked the
granularity, which is the half that carries meaning and the half its own gate
(`tests/test_doc_structure.lua`, *"the README's settings table is page-granular, not per-tab"*)
now pins.

The upstream edit is one word — `Tab | Covers` → `Page | Covers` — plus a sentence saying the
per-tab view lives in `docs/settings-panel.md`. Until it lands, `README.md:69` stays as it is; a
"correction" back to `Tab` would re-open WG-56's original form and turn the gate red.
