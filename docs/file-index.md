# File index

Where each responsibility lives in the source tree. Pair this map with the actual files before editing — `WhatGroup.toc` is the source of truth for load order.

## Source files

| File | Responsibility |

| `WhatGroup.toc` | Manifest. Interface line (`120007`), Title, Notes, Author, Version, `IconTexture`, `SavedVariables = WhatGroupDB`, `OptionalDeps` (includes `LibSharedMedia-3.0`), `DefaultState = enabled`, `Category-enUS = Chat`, `X-License = MIT`, `X-Standard`, `X-Curse-Project-ID`. Then the load order: lib `.lua` files (order: `LibStub` → `CallbackHandler-1.0` → `AceAddon-3.0` → `AceEvent-3.0` → `AceConsole-3.0` → `AceTimer-3.0` → `AceDB-3.0`), then `AceGUI-3.0.xml` (which pulls in `widgets/`), then `LibSharedMedia-3.0\lib.xml`, then `LibKa0s\LibKa0s.xml` **last** among the libraries, then the addon `.lua` files grouped by folder in the mandated section order (toc-file-§5 / WG-14): `# Locales`: `locales/enUS.lua`; `# Core`: `core/CoreSetup.lua` → `core/Util.lua` → `core/Compat.lua` → `core/Database.lua` → `core/WhatGroup.lua` → `core/DebugLogSetup.lua`; `# Defaults`: `defaults/Profile.lua` → `defaults/TeleportSpells.lua`; `# Modules`: `modules/Frame.lua`; `# Settings`: `settings/Schema.lua` → `settings/OptionsSetup.lua` → `settings/Panel.lua` → `settings/Slash.lua`. AceHook-3.0 is intentionally **not** vendored — see `core/WhatGroup.lua` for the rationale. |
| `core/CoreSetup.lua` | Wires the addon into `LibKa0s-Core-1.0`. **First in `# Core`**, because `core/WhatGroup.lua` takes the printer as a file-scope upvalue and a seam publishing after that line would be a silent no-op. Publishes `NS.IsConcatSafe` / `NS.SafeToString` (the secret-safe stringifier, events-frames-taint-§8 / WG-22 — bound to the library's own function objects, not wrapped), `NS.Util.print` / `NS.Util.format` (the single prefixed, secret-safe chat printer; reclaimed as `NS.Print` / `WhatGroup._print` by `core/WhatGroup.lua`), and `NS.SKIN` / `NS.ApplySkin` / `NS.MakeCloseButton` (the shared window chrome). It publishes onto `NS.Util.print`, never `NS.Print`, because AceConsole-3.0's `:Print` mixin lands on the same namespace and would clobber it (anti-patterns #36). Two descriptor fields are this addon's: `prefix` is passed as a **function**, since `NS.PREFIX` is defined later in `core/WhatGroup.lua` and a string form would capture `nil` forever; `sink` is passed explicitly because this addon's chat output goes through the Lua global `print` rather than Core's `DEFAULT_CHAT_FRAME:AddMessage` default (which is also what the headless harness captures). Also sets `NS.LIBKA0S_MISSING` — the one shared cause clause that `core/DebugLogSetup.lua`, `settings/OptionsSetup.lua` and `settings/Slash.lua` each append their own consequence to, so a degraded install says the same thing about *why* everywhere and a different thing about *what* at each site. Without the library it degrades to short built-in fallbacks (a deliberately non-pixel-accurate skin, so a stale hand-copy can't drift from the shared table) and announces itself once, on the first line the addon prints. |
| `core/Util.lua` | `NS.Windows` (`PointOf` / `Save` / `Restore`) — standalone-window geometry persistence into `db.global.windows` (WG-26), used by the popup. The one low-level seam here with no LibKa0s equivalent; everything else this file used to own is the library's and is wired in `core/CoreSetup.lua`, which loads immediately before it. Windows persist their anchor **point** only (all standalone windows here are fixed-size), guarded on the db being ready so a pre-login show is a no-op rather than a nil index. Nothing reads `NS.PREFIX` / `NS.addon` / `NS.db` at load — every function reads them at call time. |
| `locales/enUS.lua` | Localization shell (localization-§3 / WG-07). Hangs `NS.L`, a table whose fall-back metatable returns any missing key verbatim, so routing a literal through `L[...]` is behavior-preserving before a translation exists. Loads **first** among the addon files (the `# Locales` section precedes `# Core`, toc-file-§5 / WG-14). Carries the player-facing surfaces only — notify lines, popup chrome, group-type labels, help header + command descriptions, reset confirmation; slash-CLI diagnostics ("unknown command", "Usage: …") are deliberately left unrouted. English-only *content* is a scope decision — see [scope.md](./scope.md); the shell itself is mandatory. |
| `core/Compat.lua` | Version-variant API shims. Hangs `NS.Compat` and is the **sole caller** of `C_Spell.*`, the legacy `GetSpell*` globals, `IsSpellKnown`, and `C_LFGList.GetActivityInfoTable` — so a patch that renames one changes this file only. `GetSpellName` / `GetSpellTexture` / `GetSpellLink` / `IsSpellKnown` / `GetActivityInfoTable`; each degrades to a safe default (`nil` / `false`) rather than throwing when the underlying API is absent. The surface is scoped to what the addon actually routes — compat-§1 mandates *routing* every deprecated call through `Compat`, not a fixed shim list, so an unused shim is dead code rather than compliance. |
| `core/Database.lua` | SavedVariables schema version + migration seam (toc-file-§2 / savedvariables-§1 / WG-08). `NS.SCHEMA_VERSION` (currently `1`) and `NS:RunMigrations()`, called once from `OnInitialize` right after `AceDB:New` and before any code reads the profile. Idempotent; the step body is intentionally empty — the seam exists so the first real migration lands here rather than being retrofitted. Logs a `[Migrate]` line only when the version actually moves. |

Houses `OnInitialize` (also calls `RunMigrations`) / `OnEnable` (registers the two events, snapshots `wasInGroup`, and calls the idempotent `Settings.Register()` so the AddOns entry exists at login — | `core/DebugLogSetup.lua` | Wires the addon into `LibKa0s-DebugLog-1.0` (debug-logging §). The console window, the copy window, the two line formatters, the ring buffer, the scrollbar sync, the line counter and the enable seam are all the library's; this file publishes `NS.DebugLog` (the instance) and the global `NS.Debug(tag, fmt, …)` sink, bound bare rather than wrapped so `NS.Debug("Set", "%s = %s", …)` keeps working. Descriptor: `name` (seeds the same `WhatGroupDebugWindow` / `WhatGroupDebugCopyWindow` / `WhatGroupDebugCopyScroll` frame globals the hand-written console used), `title`, `font = NS.FONT_MONO`, `slash`, the `isEnabled` / `setEnabled` pair over the session-only `NS.State.debug` (the flag stays the host's — the panel and the slash verb read it too, so a library copy would be a second truth), call-time `print` / `safeToString` forwarders, `initSummary` (which defers to `WhatGroup:InitSummary()`; the library owns *when* it is emitted — on enable, since the flag is off at login), and `onVisibilityChanged`, which re-runs `Helpers.RefreshAll` so the General page's console checkbox mirrors a window closed with Esc or the ×. No `L`, no `skin`, no `applySkin`, no `makeCloseButton`: as of Core minor 3 the library's own default **is** the normative Ka0s window edge, and the × on a library-drawn window is the library's. Loads **after** `core/WhatGroup.lua` — a move from where the hand-written console sat — because the library validates `font`, `title`, `name`, `isEnabled` and `setEnabled` at `:New` time and both `NS.FONT_MONO` and `NS.State.debug` are defined there; nothing calls `NS.Debug` at file load, so the move costs nothing. | `defaults/Profile.lua` | Profile default VALUES (savedvariables-§2 / WG-24). Hangs `NS.C`, a nested table (`enabled`, `frame.autoShow`, `notify.*`) that is the single place any profile default is hardcoded. Each `settings/Schema.lua` row references its value via `default = NS.C.<path>`, so the schema stays the single source of settings *structure* while values live here. Loads before `settings/Schema.lua` (the `# Defaults` section precedes `# Settings`). |
| `defaults/TeleportSpells.lua` | mapID → Path-of teleport spell ID lookup. Populates `NS.TeleportSpells` (referenced by `WhatGroup:GetTeleportSpell`, where `self == NS`). Keyed by the dungeon's instance map ID — stable across seasons, unlike LFG `activityID`. Values are either a single spellID (number) or a list `{ id1, id2 }` for dungeons whose teleport has been re-issued under a new spell ID over time (the resolver picks whichever the player has learned via `IsSpellKnown`). Writes straight to `NS`, so its load order relative to `core/WhatGroup.lua` is irrelevant. Sectioned by expansion; per-row trailing comment is the dungeon name. Adding a row = appending to the table — see [common-tasks.md → Add a dungeon teleport spell mapping](./common-tasks.md#add-a-dungeon-teleport-spell-mapping). |
| `settings/Schema.lua` | Schema rows + schema/db Helpers. Stamps `WhatGroup.Settings = { Schema, Helpers }` and hangs the schema-access Helpers on it. Schema rows are appended via `add{}` calls in source order — order = panel render order. Helpers here: `Get` / `RawSet` / `Set` / `FindSchema`, `ValidateSchema`, `RestoreAllDefaults` (popup-confirmed via `WHATGROUP_RESET_ALL`) / `ApplyDefault` / `RefreshAll`; `BuildDefaults` and `EnsureResetPopup` hang on `Settings` itself rather than on `Helpers`. `Helpers.Set` is the orchestrated single write-path — writes through `RawSet`, fires the row's `onChange`, then runs `RefreshAll` (with `opts.skipOnChange` / `opts.skipRefresh` escape hatches). `Helpers.RawSet` is the side-effect-free write reserved for callers that genuinely need it (none today). The refresher registry and the panel list used to live here (`_refreshers` / `_refresherOrder` / `_panels`); they are now the library's, **per-ctx** rather than per-addon, so a re-render reassigns the list instead of leaving a released widget's closure behind (options-ui-§11). `BuildDefaults` walks the schema and threads each row's `default` (a `NS.C.<path>` reference, WG-24) into `profile.*`, and seeds `global.schemaVersion` + an empty `global.windows` (WG-26). `Settings.EnsureResetPopup` is **lazy** — writes `StaticPopupDialogs["WHATGROUP_RESET_ALL"]` on first call (Defaults button or `/wg resetall`); the same OnAccept body backs both routes. Lazy because writing to a Blizzard-protected surface at PLAYER_LOGIN taints GameMenu's button callbacks. Its file-local `Helpers` upvalue keeps pointing at the pre-move table on purpose — the members are the same function objects and no state lives on either table. |
| `settings/OptionsSetup.lua` | Wires the addon into `LibKa0s-Options-1.0`. **The instance IS `Settings.Helpers`** (options-ui-§1): the library instance is created here, `settings/Schema.lua`'s data seams are copied **onto** it, and the instance is what gets published — never the other direction, because the library resolves its own members off the instance at call time. The one deliberate collision is `RestoreAllDefaults`: the **host's** wins (LIBKA0S-08), because it wipes `db.profile` first — which drops keys left by a removed or renamed row — and coalesces the per-row `[Set]` lines into one `[Reset]` summary. The library's per-page `RestoreDefaults(pageKey, ctx)` is a different verb with a different arity and is untouched. Descriptor: `parentTitle`, `mainPanelName = "WhatGroupParentPanel"`, `print` / `debug`, the `get` / `set` / `applyDefault` write seam (the same one the CLI takes, so a checkbox click and `/wg set` are one path), `rowsForPage` / `allRows` (one page, so every row belongs to it), `validate`, and `buildMain`, which hands the landing-page body back to `settings/Panel.lua`. Also wraps `SetRenderer` and `EnsureDefaultsButton` **on the instance** so the panel body and the Defaults button still build on the **next** frame via `C_Timer.After(0, …)` — the library calls both synchronously inside `OnShow`, and this addon keeps its taint deferral (see [wow-quirks.md](./wow-quirks.md)); the wrapped renderer `pcall`s and names the failing page, since the library's own `pcall` has already returned by then. `RefreshAll` is aliased to `RefreshScalars` — writing a value does not change which rows exist. Its no-library stub is the **one documented exception** to the honest-line rule: everything here is a load-completing no-op, because this addon's measured load-time use of the module is empty and `tests/test_libka0s.lua` pins that by comparing the schema row count with the library absent against a full load. Loads after `settings/Schema.lua` and before `settings/Panel.lua`. |

## Embedded libraries

Vendored under `libs/`. Order in `WhatGroup.toc` is dependency order:

1. `LibStub` — every Ace3 module's bootstrap.
2. `CallbackHandler-1.0` — needed by AceEvent.
3. `AceAddon-3.0` — `NewAddon`, `OnInitialize` / `OnEnable` lifecycle.
4. `AceEvent-3.0` — `RegisterEvent`, event handler dispatch.
5. `AceConsole-3.0` — `RegisterChatCommand`.
6. `AceTimer-3.0` — `ScheduleTimer` / `CancelTimer`; backs the one-shot notify delay (WG-17).
7. `AceDB-3.0` — `WhatGroupDB` storage.
8. `AceGUI-3.0` (loaded via its `.xml`) — checkbox / slider / button / heading widgets used by the settings panel.
9. `LibSharedMedia-3.0` (loaded via its `lib.xml`) — media registry; `WhatGroup.lua` registers the vendored JetBrains Mono font with it at load so the debug console can render monospace.
10. `LibKa0s` (loaded via its `LibKa0s.xml`, **last**) — the shared Ka0s library. The XML lists all eight files in dependency order: `Core.lua`, `DebugLog.lua`, `Slash.lua`, `Options.lua`, `OptionsWidgets.lua`, `OptionsScroll.lua`, `Perf.lua`, `PerfPanel.lua`. This addon takes four of its five majors — `LibKa0s-Core-1.0`, `LibKa0s-DebugLog-1.0`, `LibKa0s-Options-1.0` and `LibKa0s-Slash-1.0` — one wiring file each (`core/CoreSetup.lua`, `core/DebugLogSetup.lua`, `settings/OptionsSetup.lua`, `settings/Slash.lua`). `LibKa0s-Perf-1.0` is **declined** on structural grounds: there is no hot path to measure (no `OnUpdate`, no ticker, no repeating timer), and `suspend` would stop a *capture* addon capturing, so a measurement window would cost the player the group info they joined for. The folder is still vendored whole and both Perf files still load — whole-folder vendoring, anti-patterns #48; what is declined is the wiring. See `LIBKA0S-15` in `docs/pending/LEDGER.md`.

`AceHook-3.0` was previously vendored (for `SecureHook` / `RawHook`), but both have been replaced with direct Blizzard `hooksecurefunc` calls — AceHook's wrappers leave per-invocation closures that taint Blizzard's secure-execute chain on Logout. The library directory has been removed from `libs/`.

Libs are copied as-is from Ka0s KickCD (`/mnt/d/Profile/Users/Tushar/Documents/GIT/KickCD/libs/`) so versions stay aligned across the user's addons — except `LibSharedMedia-3.0`, copied from Ka0s AbsorbTracker alongside its JetBrains Mono font, and `LibKa0s`, vendored whole from the sibling repo `../LibKa0s`. Refresh by re-copying those directories.
