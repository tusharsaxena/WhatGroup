# Module map

Where each responsibility lives in the source tree. Pair this map with the actual files before editing — `WhatGroup.toc` is the source of truth for load order.

## Source files

| File | Responsibility |
|------|----------------|
| `WhatGroup.toc` | Manifest. Interface line (`120100`), Title, Notes, Author, Version, `IconTexture` (the addon's own `media\logos\whatgroup.logo.128.tga`, toc-file-§1 / launcher-§4, not the Blizzard file id it carried before the launcher), `SavedVariables = WhatGroupDB`, `OptionalDeps` (includes `LibSharedMedia-3.0`, `LibDataBroker-1.1` and `LibDBIcon-1.0`), `DefaultState = enabled`, `Category-enUS = Chat`, `X-License = MIT`, `X-Standard`, `X-Curse-Project-ID`. Then the load order: lib `.lua` files (order: `LibStub` → `CallbackHandler-1.0` → `AceAddon-3.0` → `AceEvent-3.0` → `AceConsole-3.0` → `AceTimer-3.0` → `AceDB-3.0`), then `AceGUI-3.0.xml` (which pulls in `widgets/`), then `LibSharedMedia-3.0\lib.xml`, then `LibDataBroker-1.1` and `LibDBIcon-1.0` (the launcher's two, launcher-§1), then `LibKa0s\LibKa0s.xml` **last** among the libraries, then the addon `.lua` files grouped by folder in the mandated section order (toc-file-§5 / WG-14): `# Locales`: `locales/enUS.lua`; `# Core`: `core/CoreSetup.lua` → `core/MediaSetup.lua` → `core/Util.lua` → `core/Compat.lua` → `core/EnvSetup.lua` → `core/Database.lua` → `core/WhatGroup.lua` → `core/DebugLogSetup.lua` → `core/LauncherSetup.lua` → `core/LifecycleSetup.lua`; `# Defaults`: `defaults/Profile.lua` → `defaults/TeleportSpells.lua`; `# Modules`: `modules/Frame.lua` → `modules/Diagnostics.lua`; `# Settings`: `settings/Schema.lua` → `settings/OptionsSetup.lua` → `settings/Panel.lua` → `settings/Slash.lua`. Three of the eight LibKa0s wiring files sit where they do because of what reads what at load: `core/MediaSetup.lua` must publish `NS.MediaFont` before `core/WhatGroup.lua` resolves `NS.FONT_MONO` from it; `core/DebugLogSetup.lua` needs `NS.FONT_MONO` and `NS.State.debug`, both defined in `core/WhatGroup.lua`; `settings/OptionsSetup.lua` needs the data seams `settings/Schema.lua` hangs on `Settings.Helpers`. AceHook-3.0 is intentionally **not** vendored — see `core/WhatGroup.lua` for the rationale. |
| `core/CoreSetup.lua` | Wires the addon into `LibKa0s-Core-1.0`. **First in `# Core`**, because `core/WhatGroup.lua` takes the printer as a file-scope upvalue and a seam publishing after that line would be a silent no-op. Publishes `NS.IsConcatSafe` / `NS.SafeToString` (the secret-safe stringifier, events-frames-taint-§8 / WG-22 — bound to the library's own function objects, not wrapped), `NS.Util.print` / `NS.Util.format` (the single prefixed, secret-safe chat printer; reclaimed as `NS.Print` / `WhatGroup._print` by `core/WhatGroup.lua`), and `NS.SKIN` / `NS.ApplySkin` / `NS.MakeCloseButton` (the shared window chrome). `NS.MakeCloseButton` is the one seam here that is **wrapped** rather than bound: it supplies `addonName` as the library's third argument, which is what lets the shared `close` mark be drawn at all — a vendored library cannot work out which folder it was copied into, and a two-of-three passthrough builds a perfectly good button drawing a multiplication sign, silently (anti-patterns #64). It publishes onto `NS.Util.print`, never `NS.Print`, because AceConsole-3.0's `:Print` mixin lands on the same namespace and would clobber it (anti-patterns #36). Two descriptor fields are this addon's: `prefix` is passed as a **function**, since `NS.PREFIX` is defined later in `core/WhatGroup.lua` and a string form would capture `nil` forever; `sink` is passed explicitly because this addon's chat output goes through the Lua global `print` rather than Core's `DEFAULT_CHAT_FRAME:AddMessage` default (which is also what the headless harness captures). Also sets `NS.LIBKA0S_MISSING` — the one shared cause clause that `core/DebugLogSetup.lua`, `settings/OptionsSetup.lua` and `settings/Slash.lua` each append their own consequence to, so a degraded install says the same thing about *why* everywhere and a different thing about *what* at each site. Without the library it degrades to short built-in fallbacks (a deliberately non-pixel-accurate skin, so a stale hand-copy can't drift from the shared table) and announces itself once, on the first line the addon prints. |
| `core/MediaSetup.lua` | Wires the addon into `LibKa0s-Media-1.0` (library-stack-§8). Publishes `NS.Icon(name)` → `Media.Icon(addonName, name)` and `NS.MediaFont(name)` → `Media.Font(addonName, name)`, both `nil` without the library, and calls `Media.RegisterLSM(addonName)` at **file load** — replacing this addon's own `LSM:Register("font", "JetBrains Mono", …)`, so every Ka0s addon now registers one set of bytes under one key. `addonName` is the addon's **folder** name, taken from the file's first vararg; a texture path is absolute from `Interface\AddOns\` and a vendored library has no way to infer it. **Second in `# Core`, and the slot is load-bearing**: `core/WhatGroup.lua` resolves `NS.FONT_MONO` from `NS.MediaFont` at load, and `core/DebugLogSetup.lua` hands that value to a descriptor the library validates as a string. Icon paths come back **extensionless** (the client appends `.tga`); a path carrying the extension draws nothing and raises nothing. Does no frame work, which is why file-load registration is safe here. |
| `core/Util.lua` | `NS.Windows` (`PointOf` / `Save` / `Restore`) — standalone-window geometry persistence into `db.global.windows` (WG-26), used by the popup. `NS.Windows` is the named owner of that store (`architecture-§5` named non-setting state). `Save` writes it on drag-stop, and `WhatGroup:ResetFramePosition()` in `modules/Frame.lua` is its only other writer. The one low-level seam here with no LibKa0s equivalent; everything else this file used to own is the library's and is wired in `core/CoreSetup.lua`, which loads immediately before it. Windows persist their anchor **point** only (all standalone windows here are fixed-size), guarded on the db being ready so a pre-login show is a no-op rather than a nil index. Nothing reads `NS.PREFIX` / `NS.addon` / `NS.db` at load — every function reads them at call time. |
| `locales/enUS.lua` | Localization shell (localization-§3 / WG-07). Hangs `NS.L`, a table whose fall-back metatable returns any missing key verbatim, so routing a literal through `L[...]` is behavior-preserving before a translation exists. Loads **first** among the addon files (the `# Locales` section precedes `# Core`, toc-file-§5 / WG-14). Carries the player-facing surfaces only — notify lines, popup chrome, group-type labels, help header + command descriptions, reset confirmation; slash-CLI diagnostics ("unknown command", "Usage: …"), strings that double as identifiers ("General", "Master controls", "Ka0s WhatGroup") and strings LibKa0s-Options-1.0 authors ("Defaults", the combat-refusal notice) are deliberately left unrouted, ratified in `ARCHITECTURE.md` → `## Documented deviations`. Every key in the table has an `L[...]` reader. English-only *content* is a scope decision — see [scope.md](./scope.md); the shell itself is mandatory. |
| `core/Compat.lua` | Version-variant API shims, and the `LibKa0s-Compat-1.0` seam. Hangs `NS.Compat`, the **one surface** the addon reads `C_Spell.*`, the legacy `GetSpell*` globals, `C_SpellBook.IsSpellKnown` and the `IsSpellKnown` global, and `C_LFGList.GetActivityInfoTable` through, and the one place that asks whether `LinkTypes.AddOn` and `EventRegistry` exist for the chat link's detection — so a patch that renames one changes this file or the library, and nothing else. `GetSpellName` and `GetSpellTexture` are the library's own members, and the two cooldown shims are built on its `GetSpellCooldown`; without the library those four answer its documented no-answer values. Its own shims are `GetSpellLink` / `IsSpellKnown` / `GetSpellCooldownRemaining` / `GetSpellCooldownTimes` / `GetActivityInfoTable` / `AddOnLinkType` — six, four of them spell readers. Each degrades to a safe default (`nil` / `false` / `0`) rather than throwing when the underlying API is absent; the two cooldown readers are kept apart on purpose (only `GetSpellCooldownRemaining` applies the 1.5s GCD floor), and [compat-layer.md](./compat-layer.md) carries the reasoning. The surface is scoped to what the addon actually routes — `compat` mandates *routing* every deprecated call through `Compat`, not a fixed shim list, so an unused shim is dead code rather than compliance. |
| `core/EnvSetup.lua` | Wires the addon into `LibKa0s-Env-1.0` (library-stack-§7). Publishes `NS.Meta(field)` → `Env.GetAddOnMetadata(addonName, field)` and `NS.Version()` → `Env.Version(addonName, WhatGroup.VERSION)`, each falling back to the C_AddOns-then-global ladder the addon ran before the library so a degraded install still reads its own TOC. **Replaced two INLINE copies** of that ladder — `settings/Slash.lua`'s `version()` and `settings/Panel.lua`'s `addNotesLine` — neither of which was ever in `core/Compat.lua`, which is why an audit of the shim file reported this addon as having no copy at all. `addonName` is the addon's **folder** name from the file's first vararg; a vendored library cannot infer which folder it sits in, and `## Title` reads "Ka0s WhatGroup". **After `core/Compat.lua`, and the slot is conventional, not load-bearing**: nothing resolves at load beyond the `LibStub` lookup and both call sites read inside a function. Publishes no zone or map-id member — this addon stamps neither. |
| `core/Database.lua` | SavedVariables schema version + migration seam (toc-file-§2 / savedvariables-§1 / WG-08). `NS.SCHEMA_VERSION` (currently `1`) and `NS:RunMigrations()`, called once from `OnInitialize` right after `AceDB:New` and before any code reads the profile. `NS.MIGRATIONS[N]` holds the step from N-1 to N; the only one today is the no-op 0 -> 1 stamp, because `global.schemaVersion` is declared 0 so the stamp survives AceDB's logout strip. The runner advances the stamp only past a step that returned. Idempotent; the seam exists so the first real migration lands here rather than being retrofitted. Logs a `[Migrate]` line only when the version actually moves. |
| `core/WhatGroup.lua` | AceAddon shell + capture pipeline. Builds the addon on the shared private namespace via `LibStub("AceAddon-3.0"):NewAddon(NS, addonName, "AceConsole-3.0", "AceEvent-3.0", "AceTimer-3.0")` and sets `NS.addon` — **no `_G.WhatGroup`**. **Installs both of its subscriptions at file-load top-level**: the direct `hooksecurefunc` post-hook on `C_LFGList.ApplyToGroup`, and the details chat link's `EventRegistry:RegisterCallback("SetItemRef", …)`, filtered to `addon:WhatGroup:` links. Where `NS.Compat.AddOnLinkType()` answers nil, the second is a `hooksecurefunc("SetItemRef", …)` post-hook over the old `WhatGroup:show` link instead. Houses `OnInitialize` (also calls `RunMigrations`) / `OnEnable` (registers the four events — the two capture events plus the `PLAYER_REGEN_DISABLED` / `PLAYER_REGEN_ENABLED` pair that both route to `OnCombatStateChanged`, snapshots `wasInGroup`, and calls the idempotent `Settings.Register()` so the AddOns entry exists at login — **no hook installation**, those are at file-load), the `NS.PREFIX = "\|cff00FFFF[WG]\|r"` constant plus the secret-safe chat seam aliased from `core/CoreSetup.lua` as the file-local `p` / `NS.Print` / `WhatGroup._print`, the two `RegisterChatCommand` calls (`wg` / `whatgroup`, both routed to `OnSlashCommand`, which `settings/Slash.lua` defines), the `NS.FONT_MONO_NAME` / `NS.FONT_MONO` constants — the latter resolved from `core/MediaSetup.lua`'s seam, falling back to the client's own `STANDARD_TEXT_FONT` rather than to a dead path (consumed by `core/DebugLogSetup.lua`), the session-only `NS.State.debug` flag, the session-only locals (`capturesByResult`, `pendingApplications`, `wasInGroup`, `notifiedFor`) plus the `self.notifyTimer` AceTimer handle, the `LFG_LIST_APPLICATION_STATUS_UPDATED` and `GROUP_ROSTER_UPDATE` handlers (the status handler's two short arms are the file-locals `pairApplication` and `dropApplication`, named rather than inlined so the function stays inside the CCN 15 ceiling (`automated-tests-§3`, `performance-§10`) that the `inviteaccepted` merge needs the room for), the `OnCombatStateChanged` handler both combat edges share (on `PLAYER_REGEN_DISABLED` it first ends test mode through `EndTestModeForCombat`; then one `ApplyFrameVisibility` call, told which edge it is by the event name rather than by `InCombatLockdown()`, which can still read stale on the frame `PLAYER_REGEN_DISABLED` fires), the `_TryFireJoinNotify(reason)` dual-path notify scheduler (schedules via `self:ScheduleTimer`, cancels via `self:CancelTimer` — AceTimer-3.0, WG-17), the `WhatGroup:WipeCapture(reason)` consolidator (called from group-leave with no reason, and from the master-switch off-flip with `"addon disabled"` — a passed reason emits a one-line `[Capture] wiped` material-effect log only when something was in flight, debug-logging-§10), the `WhatGroup:InitSummary()` builder for the one-line `[Init]` session summary (the debug-logging-§5 identity fields `WhatGroup v<version>, schema v<schemaVersion>, profile '<profile>'` plus the current runtime state) that the `DebugLog:SetEnabled` seam appends on enable, right after the bracket line (debug-logging-§5 / debug-logging-§8), the `ShowNotification` chat-output builder, the `WhatGroup.Labels` namespace (`PLAYSTYLE`, `GetGroupTypeLabel`, `GetPlaystyleLabel`) shared with the popup, the `WhatGroup:CaptureGroupInfo(searchResultID)` capture builder, the `WhatGroup:ResolveSearchResultID(appID)` bridge (an application id to a search-result id through the documented `C_LFGList.GetApplicationInfo`, falling back to the raw `appID` with a `[Capture]` log line if that API is missing, raises, or yields nothing — F-004; shared by the `"applied"` arm, which uses it to find the capture the apply hook already took) and its `WhatGroup:CaptureGroupInfoFromApplication(appID)` wrapper, the `WhatGroup:GetTeleportSpell(activityID, mapID)` resolver (the `TeleportSpells` table itself lives in `defaults/TeleportSpells.lua`). The slash surface is **not** here — the `COMMANDS` table, the host verbs and the `LibKa0s-Slash-1.0` descriptor all live in `settings/Slash.lua`. What stays is `WhatGroup:RunTest()`, the one body two callers share: `/wg test notify` and the panel's Test button, neither of which should reach it through the other's entry point. Beside it, `WhatGroup:SampleInfo()`, the sample capture that `RunTest` and test mode both draw on (a fresh table per call). `_TryFireJoinNotify` holds the join popup while test mode is on. `WhatGroup:CaptureSnapshot()` is the read-only view of the session-only locals for the diagnostics report (debug-logging-§14): deep copies of `capturesByResult` and `pendingApplications`, plus `wasInGroup` and whether notify already fired for the current `pendingInfo`. |
| `core/DebugLogSetup.lua` | Wires the addon into `LibKa0s-DebugLog-1.0` (debug-logging). The console window, the copy window, the two line formatters, the ring buffer, the scrollbar sync, the line counter and the enable seam are all the library's; this file publishes `NS.DebugLog` (the instance) and the global `NS.Debug(tag, fmt, …)` sink, bound bare rather than wrapped so `NS.Debug("Set", "%s = %s", …)` keeps working. Descriptor: `name` (seeds the same `WhatGroupDebugWindow` / `WhatGroupDebugCopyWindow` / `WhatGroupDebugCopyScroll` frame globals the hand-written console used), `addonName` (passed **beside** `name`, never instead of it — `name` seeds frame globals, `addonName` is what the library builds a texture path from, which is what makes the console's close, clear and copy draw the shared marks instead of a multiplication sign and two words), `title`, `font` (the library payload's TTF, or `Fonts\ARIALN.TTF` when a `CreateFont` probe shows the client cannot fetch it — debug-logging-§2's fetch-failure fallback), `slash`, the `isEnabled` / `setEnabled` pair over the session-only `NS.State.debug` (the flag stays the host's — the panel and the slash verb read it too, so a library copy would be a second truth), call-time `print` / `safeToString` forwarders, `initSummary` (which defers to `WhatGroup:InitSummary()`; the library owns *when* it is emitted — on enable, since the flag is off at login), `onVisibilityChanged`, which re-runs `Helpers.RefreshAll` so the General page's console checkbox mirrors a window closed with Esc or the ×, and the diagnostics report's three: `brandName` (`Ka0s WhatGroup`, in both markers), `diagnostics` (answers `NS.Diagnostics.Sections()`, read at run time because `modules/Diagnostics.lua` loads later) and `L`, a **plain** table carrying only `DIAG_WRITTEN`, the report's chat line through `NS.L` — never `NS.L` itself, whose key-returning metatable would put `DEBUG_ON` on the console. No `skin`, no `applySkin`, no `makeCloseButton`: as of Core minor 3 the library's own default **is** the normative Ka0s window edge, and the × on a library-drawn window is the library's. Loads **after** `core/WhatGroup.lua` — a move from where the hand-written console sat — because the library validates `font`, `title`, `name`, `isEnabled` and `setEnabled` at `:New` time and both `NS.FONT_MONO` and `NS.State.debug` are defined there; nothing calls `NS.Debug` at file load, so the move costs nothing. Without the library the stub keeps the **flag** working (so `/wg debug on` is never a lie) and loses only the window, saying so once per entry point. The console no longer persists its window position — no library hook exists for it ([LIBKA0S-05](https://github.com/tusharsaxena/WhatGroup/issues/11)). See [debug-content.md](./debug-content.md). |
| `core/LauncherSetup.lua` | Wires the addon into `LibKa0s-Launcher-1.0` (launcher-§1). Builds ONE LibDataBroker-1.1 object of `type = "launcher"` and hands that same object to LibDBIcon-1.0 — one `OnClick`, one icon, one label, so the minimap button and any broker display cannot drift apart (anti-pattern #81). Both registrations key off the addon's **folder** name, because LibDBIcon stores the button's dragged position under it. Descriptor: `name` / `icon` (`Interface\AddOns\<Folder>\media\logos\<addon>.logo.128.tga`, built from the file's first vararg exactly as `core/MediaSetup.lua` builds its paths) / `label` (**`Ka0s WhatGroup`**, the brand name in plain text — launcher-§1; deliberately not the TOC `Title`, which may carry color escapes, and not the folder name, which is the registration `name`), `minimap` **as a function** — `db.global.minimap` does not exist at file load and a table captured then is one AceDB replaces, so the library resolves it at `Register` time — `openSettings` → `WhatGroup:OpenSettings` (the `/wg config` body, and the left click on every addon), and the options menu's four pairs (Launcher minor 4, launcher-§2): `isEnabled` / `setEnabled` → `not NS.IsStoodDown()` / `WhatGroup:SlashEnabled`, `isLocked` / `toggleLock` → the profile's `locked` / `WhatGroup:SlashToggleLock` (`/wg set locked toggle`), `isTestMode` / `toggleTestMode` → `NS.State.testMode` / `WhatGroup:SlashToggleTestMode` (bare `/wg test`), and `isWindowShown` / `toggleWindow` → `WhatGroup:IsFrameOnScreen` / `WhatGroup:ToggleFrame` (the group popup, its primary window). The status tooltip is the library's (launcher-§1): the descriptor answers it with `version` (the TOC's, via `NS.Version`) and the same `isEnabled` / `isLocked` / `isTestMode`, each read on every hover. No `onTooltipShow` (there is no line of the addon's own to append; a title or click hint there would be anti-pattern #89) and no `L` (the library's own tooltip words stay its English, the ratified partial-routing deviation). `Register()` is **not** called here — `OnEnable` calls it, once the db exists; it is idempotent. Without the library the stub answers every member and keeps the stored flag working, because the write seam calls `SetShown` on every tick of the *Minimap button* checkbox; without LibDataBroker or LibDBIcon the library itself says which one is missing, once, and the addon carries on. |
| `core/LifecycleSetup.lua` | Wires the addon into `LibKa0s-Lifecycle-1.0` — **the stand-down latch** (slash-commands-§7). ONE instance, two named holds: `disabled`, taken from the stored `enabled` path (checkbox, `/wg enable` / `/wg disable`, `/wg set enabled false`, a profile switch), and `perf`, reserved for the harness this addon declines. The addon is down whenever at least one hold is taken and stands up only when the LAST is released, so releasing one cannot resurrect an addon the other still holds down; there is no `:StandUp()` member to call by accident. Descriptor: `name` / `standDown` → `NS.StandDown` (`core/WhatGroup.lua`) / `standUp` → `NS.StandUp` / `print`. Publishes `NS.IsStoodDown()`, the one question every gate in the addon asks — the show ladder, the two un-un-hookable `hooksecurefunc` bodies, the launcher's `isEnabled` (which grays the right-click menu's feature entries; the left click is not gated) and the slash dispatcher's `isEnabled`. Without the library the stub is the hold set minus the diagnostics, because the checkbox and the verbs still have to work on a degraded install. TOC slot: last in `# Core`, conventional. |
| `defaults/Profile.lua` | Profile default VALUES (savedvariables-§2 / WG-24). Hangs `NS.C`, a nested table that is the single place any profile default is hardcoded: the five Master controls values stored at the profile ROOT (`enabled`, `visibility`, `scale`, `alpha`, `locked`, options-ui-§15), plus `frame.autoShow` / `frame.width` / `frame.height` and `notify.*`. Each `settings/Schema.lua` row references its value via `default = NS.C.<path>`, so the schema stays the single source of settings *structure* while values live here. Loads before `settings/Schema.lua` (the `# Defaults` section precedes `# Settings`). |
| `defaults/TeleportSpells.lua` | mapID → Path-of teleport spell ID lookup. Populates `NS.TeleportSpells` (referenced by `WhatGroup:GetTeleportSpell`, where `self == NS`). Keyed by the dungeon's instance map ID — stable across seasons, unlike LFG `activityID`. Values are either a single spellID (number) or a list `{ id1, id2 }` for dungeons whose teleport has been re-issued under a new spell ID over time (the resolver picks whichever the player has learned via `IsSpellKnown`). Writes straight to `NS`, so its load order relative to `core/WhatGroup.lua` is irrelevant. Sectioned by expansion; per-row trailing comment is the dungeon name. Adding a row = appending to the table — see [common-tasks.md → Add a dungeon teleport spell mapping](./common-tasks.md#add-a-dungeon-teleport-spell-mapping). |
| `settings/SchemaSetup.lua` | Resolves `LibKa0s-Schema-1.0`, or else `HostSchemaStub`, and publishes it as `Settings.SchemaLib`. The stub is the library's `referenceStub` (LibKa0s `tests/test_schema.lua` at v1.56.0) trimmed to this addon: write-completing and log-silent, a deliberate duplication named by the library's Schema version-2 doc ("The degradation stub"). It carries the whole instance surface and the lib-level `SplitPath` / `Read` / `Write` / `SameValue` / `New`, pinned by `tests/test_surface_parity.lua`, and no `writeThrough` list. **Load-bearing slot:** directly above `settings/Schema.lua`, which calls its `:New` at file scope. |
| `settings/Schema.lua` | Schema rows + schema/db Helpers. Stamps `WhatGroup.Settings = { Schema, Helpers }` and hangs the schema-access Helpers on it. Schema rows are appended via `add{}` calls in source order — order = panel render order, and on a tabbed page (options-ui-§13) that means order = **tab** order. Eleven rows are declared here; the eight-row **Master controls** block is composed by `LibKa0s-Options-1.0` and spliced at the HEAD of the array by `settings/Panel.lua` (options-ui-§15), giving nineteen rows across three groups — **Master controls** (8), **Chat** (8), **Popup** (3) — each group's rows contiguous because `RenderTabbedSchema` partitions by `group` in declaration order. Two tabs carry `subgroup` headings (options-ui-§7). Builds the ONE schema runtime over the array at file scope, `Settings.SchemaLib:New{...}` (`LibKa0s-Schema-1.0`, or `settings/SchemaSetup.lua`'s stub), published as `NS.SchemaRuntime`, with no `writeThrough` list (WhatGroup#22, `options-ui-§1` route (b)). A `SESSION` table gives the two `sessionOnly` rows, `state.debugConsole` (WG-12) and `state.testMode` (bound to `WhatGroup:TestModeCheckbox()`), their own `get` / `set` through `Settings.StampClosureRows`, so they never reach `db.profile`. A `GLOBAL` table does the same for the one account-wide row, `global.minimap.shown` (launcher-§3): its closures read and write `db.global.minimap.hide` and **invert** it, because the checkbox says *shown* and LibDBIcon's own key says hidden. Helpers here: `Get` / `Set` / `FindSchema` / `ApplyDefault` (the runtime's `Get` / `Set` / `FindRow` / `ApplyDefault`), `ValidateSchema`, `RestoreAllDefaults` (popup-confirmed via `WHATGROUP_RESET_ALL`) / `RefreshAll`; `BuildDefaults`, `StampClosureRows`, `Bulk`, `ConsumeResetCount` and `EnsureResetPopup` hang on `Settings` itself rather than on `Helpers`. The runtime's `Set` is the single write-path — refuses a path no row declares, stores, logs, fires the row's `onChange`, then `announce` runs `RefreshAll`. There is no raw writer and no skip option. The refresher registry and the panel list used to live here (`_refreshers` / `_refresherOrder` / `_panels`); they are now the library's, **per-ctx** rather than per-addon, so a re-render reassigns the list instead of leaving a released widget's closure behind (options-ui-§11). `BuildDefaults` seeds `profile` from `NS.C` (so the stored shape does not depend on whether the composed rows loaded), then threads each non-`sessionOnly` row's `default` (a `NS.C.<path>` reference, WG-24) into `profile.*`, and declares `global.schemaVersion = 0` + an empty `global.windows` (WG-26). `Settings.EnsureResetPopup` is **lazy** — writes `StaticPopupDialogs["WHATGROUP_RESET_ALL"]` on first call (Defaults button or `/wg resetall`); the same OnAccept body backs both routes. Lazy because writing to a Blizzard-protected surface at PLAYER_LOGIN taints GameMenu's button callbacks. Its file-local `Helpers` upvalue keeps pointing at the pre-move table on purpose — the members are the same function objects and no state lives on either table. |
| `settings/OptionsSetup.lua` | Wires the addon into `LibKa0s-Options-1.0`. **The instance IS `Settings.Helpers`** (options-ui-§1): the library instance is created here, `settings/Schema.lua`'s data seams are copied **onto** it, and the instance is what gets published — never the other direction, because the library resolves its own members off the instance at call time. The one deliberate collision is `RestoreAllDefaults`: the **host's** wins ([LIBKA0S-08](https://github.com/tusharsaxena/WhatGroup/issues/10)), because it is a `db:ResetProfile()` (options-ui-§12) rather than a row-by-row sweep — which is what drops keys left by a removed or renamed row, and the only mechanism that can restore a stored array — and because its reset is logged once, as `[Set] reset profile '<name>' to defaults (N rows)` from the `OnProfileReset` handler, rather than one `[Set]` per row (debug-logging-§10). The library's per-page `RestoreDefaults(pageKey, ctx)` is a different verb with a different arity and is untouched. ## Load order

`WhatGroup.toc` is the source of truth. Order is dependency, not alphabetical:

1. **libs/** — `LibStub` → `CallbackHandler-1.0` → `AceAddon-3.0` → `AceEvent-3.0` → `AceConsole-3.0` → `AceTimer-3.0` → `AceDB-3.0` → `AceGUI-3.0` (via its `.xml`, because that pulls in `widgets/`) → `LibSharedMedia-3.0` (via its `lib.xml`) → `LibDataBroker-1.1` → `LibDBIcon-1.0` → **`LibKa0s`** (last, via its own `LibKa0s.xml`, which loads the files `libs/LibKa0s/LibKa0s.xml` lists, `Core.lua` first; every other major refuses to register without `Core`, which is why the folder is vendored whole).
2. **`locales/enUS.lua`** — `NS.L`, a metatable shell whose missing keys return themselves. Loads first among the addon files (the `# Locales` section precedes `# Core`, toc-file-§5 / WG-14), so `NS.L` is available to every later file; callers still reference `NS.L[...]` at runtime by convention. Every *player-facing* string the addon authors routes through it; three classes deliberately do not, and the deviation table in [ARCHITECTURE.md → Documented deviations](./ARCHITECTURE.md#documented-deviations) carries the reasoning and the re-check trigger (localization-§3 / WG-07).
3. **`core/CoreSetup.lua`** — wires `LibKa0s-Core-1.0` and publishes the seams under the keys the addon already reads: `NS.IsConcatSafe` / `NS.SafeToString` (the secret-safe stringifier, events-frames-taint-§8 / WG-22), `NS.Util.print` (the prefixed secret-safe chat printer, aliased to `NS.Print` / `WhatGroup._print` by `core/WhatGroup.lua`), and `NS.SKIN` / `NS.ApplySkin` / `NS.MakeCloseButton` (the shared Ka0s window chrome, standalone-windows). Also publishes `NS.LIBKA0S_MISSING`, the one cause clause every other seam appends to. **First** in `# Core`, and three facts put it there: `core/WhatGroup.lua` takes the printer as a file-scope upvalue (`local p = NS.Util.print`), so a seam that published later would be a silent no-op; the printer is published on `NS.Util.print` rather than `NS.Print`, out of reach of AceConsole's `:Print` embed (anti-patterns #36); and `NS.PREFIX` is defined two files later, so `prefix` is passed in its **function** form, which Core re-reads on every call. `sink` is passed explicitly too — this addon prints through the Lua global `print`, not `DEFAULT_CHAT_FRAME:AddMessage`.
4. **`core/MediaSetup.lua`** — wires `LibKa0s-Media-1.0` and publishes `NS.Icon(name)` / `NS.MediaFont(name)`, both answering `nil` without the library, then calls `Media.RegisterLSM(addonName)` at file load. **This slot is load-bearing**, not conventional: `core/WhatGroup.lua` resolves `NS.FONT_MONO` from `NS.MediaFont` at load and `core/DebugLogSetup.lua` hands that value to a descriptor the library validates as a string, so a later slot would leave both reading `nil`. `addonName` is the addon's **folder** name — a texture path is absolute from `Interface\AddOns\` and a vendored library cannot infer which folder it was copied into. Does no frame work, which is what makes file-load registration safe here (library-stack-§8).
5. **`core/Util.lua`** — what the library does not own: `NS.Windows`, standalone-window geometry persistence (WG-26).
6. **`core/Compat.lua`** — hangs `NS.Compat` on the shared namespace. Version-variant spell / LFG shims plus the chat-link detection — six of its own: `GetSpellLink` / `IsSpellKnown` / `GetSpellCooldownRemaining` / `GetSpellCooldownTimes` / `GetActivityInfoTable` / `AddOnLinkType`, beside the library's `GetSpellName` / `GetSpellTexture`, wired by identity; the one surface the addon reads `C_Spell.*` / legacy globals / `C_LFGList.GetActivityInfoTable` through, and the one place that asks whether `LinkTypes.AddOn` and `EventRegistry` exist. It is also the `LibKa0s-Compat-1.0` seam (since v1.55.0): `GetSpellName` and `GetSpellTexture` are the library's own members, and the two cooldown shims read the library's `GetSpellCooldown` and keep this addon's GCD floor and two-value truncation. Without the library those readers take the documented reader arm (`nil`, `0, 0`) and copy none of its ladder. Detail: [docs/compat-layer.md](./compat-layer.md).
7. **`core/EnvSetup.lua`** — wires `LibKa0s-Env-1.0` and publishes the TOC-manifest readers `NS.Meta(field)` and `NS.Version()`, the seam behind the `version` verb's banner and the settings landing page's Notes line. Both were inline ladders before — `settings/Slash.lua`'s `version()` and `settings/Panel.lua`'s `addNotesLine`, neither of them in `core/Compat.lua` — and both fall back to `C_AddOns.GetAddOnMetadata` (then the legacy global) without the library, so a degraded install still reads its own TOC instead of printing a blank. `addonName` is the **folder** name again, for the `core/MediaSetup.lua` reason. TOC slot: after `core/Compat.lua` and before the two files that read it; nothing resolves at load beyond the `LibStub` lookup, so the position is conventional.
8. **`core/Database.lua`** — `NS.SCHEMA_VERSION`, the `NS.MIGRATIONS` step table and `NS:RunMigrations()` (step-driven, idempotent, called once after `AceDB:New`); establishes the migration seam (WG-08).
9. **`core/WhatGroup.lua`** — `local WhatGroup = AceAddon:NewAddon(NS, addonName, "AceConsole-3.0", "AceEvent-3.0", "AceTimer-3.0")` (mixes Ace methods, incl. `ScheduleTimer`/`CancelTimer`, into `NS`; `NS.addon = WhatGroup`). Seeds `NS.State.debug=false`, `NS.PREFIX`, aliases the `core/CoreSetup.lua` printer as the file-local `p` / `NS.Print` / `WhatGroup._print` (the reclaim from AceConsole's embed, anti-patterns #36), and `NS.FONT_MONO_NAME` / `NS.FONT_MONO` (the latter resolved from `core/MediaSetup.lua`'s `NS.MediaFont` seam, which is why that file's TOC slot is load-bearing; the LibSharedMedia registration moved there too). Then **at file-load top-level** installs its two subscriptions before any later boot-time work, so GameMenu's `InitButtons` sees a clean secure context: the direct `hooksecurefunc` post-hook on `C_LFGList.ApplyToGroup`, and the details chat link's `EventRegistry:RegisterCallback("SetItemRef", …)`. Where `NS.Compat.AddOnLinkType()` is nil, the second is a `hooksecurefunc("SetItemRef")` post-hook instead. Defines `OnInitialize` / `OnEnable` / the capture handlers / `WhatGroup:RunTest` / `WhatGroup.Labels` (`PLAYSTYLE` / `GetGroupTypeLabel` / `GetPlaystyleLabel`). Module-locals `capturesByResult`, `pendingApplications`, `wasInGroup`, `notifiedFor` initialize to empty / `false` / `nil`; the notify timer handle lives on `self.notifyTimer` (AceTimer). Its user-facing strings reference `NS.L[...]` at **runtime**; `NS.L` is already available since `locales/enUS.lua` now loads first.
10. **`core/DebugLogSetup.lua`** — wires `LibKa0s-DebugLog-1.0` and hangs `NS.DebugLog` + the bare `NS.Debug(tag, fmt, …)` sink on the namespace. The library owns the `WhatGroupDebugWindow` console, its Copy window, both line formatters, the ring buffer, the scrollbar sync and the enable seam; the descriptor supplies the frame-name prefix, the title, the mono font path, where the flag lives, what the `[Init]` summary says and who to tell when the window opens or closes. Loads **after** `core/WhatGroup.lua`, which is a move from where the hand-written console sat: the library validates `font`, `title`, `isEnabled` and `setEnabled` at `:New` time, and both `NS.FONT_MONO` and `NS.State.debug` are defined there. Nothing calls `NS.Debug` at file load, so the move costs nothing.
11. **`core/LauncherSetup.lua`** — wires `LibKa0s-Launcher-1.0` and hangs `NS.Launcher` on the namespace: ONE LibDataBroker object of `type = "launcher"`, registered with LibDBIcon under the same FOLDER name (LibDBIcon keys the button's saved position by it). The descriptor supplies the icon, the label, `minimap` **as a function** (`db.global.minimap` does not exist at file load, and a table captured then is one AceDB replaces), `openSettings` → `WhatGroup:OpenSettings` (the left click, in either state), the options menu's four accessor-and-toggle pairs — Enabled, Locked, Test mode, Show window — each toggle the body its slash verb runs (Launcher minor 4 builds the menu and grays all but Enabled while `isEnabled` → `not NS.IsStoodDown()` answers false; see [stand-down.md → The launcher click](./stand-down.md#the-launcher-click)), and the tooltip's `version`, which with the same accessors Launcher minor 3 draws on every hover. Loads after `core/DebugLogSetup.lua` (which publishes `NS.Debug`); conventional rather than load-bearing, since every seam it holds is read inside a closure at click or `Register` time. **`Register()` is called from `OnEnable`**, not here.
12. **`core/LifecycleSetup.lua`** — wires `LibKa0s-Lifecycle-1.0` and publishes `NS.Lifecycle` plus `NS.IsStoodDown()`, the one question every gate in the addon asks (the show ladder, both un-un-hookable `hooksecurefunc` bodies, the launcher menu's `isEnabled`, the dispatcher's `isEnabled`). ONE latch, two named holds — `disabled`, written from the stored `enabled` path, and `perf`, reserved for the harness this addon declines; the descriptor points `standDown` / `standUp` at `NS.StandDown` / `NS.StandUp` in `core/WhatGroup.lua`. Without the library the stub is the hold set minus the diagnostics, because the checkbox and the verbs still have to work on a degraded install. Last in `# Core` and conventional: both host callbacks resolve `NS.addon` members at CALL time, and the first call comes from `OnEnable`. Detail: [stand-down.md](./stand-down.md).

Loads before `settings/Schema.lua` (the `# Defaults` section precedes `# Settings`).

15. **`modules/Frame.lua`** — `local WhatGroup = NS.addon`; file-load runs only the `WhatGroup:ShowFrame()` method assignment. Everything else (the `WhatGroupFrame`, the secure teleport button, the `UISpecialFrames` registration of the `WhatGroupFrameEscape` ESC proxy, `MakeLabel` calls) is wrapped in `buildFrame()`, called from the first `ShowFrame()`; the popup persists its position via `NS.Windows` (WG-26). Loads after `# Core` (needs `NS.addon` / `NS.L` / `NS.Windows`) and before `# Settings`, referencing nothing from the settings layer at load. Same lazy-creation reasoning as the Settings panel + reset popup.
16. **`modules/Diagnostics.lua`** — defines the report's section functions and `NS.Diagnostics.Sections()`; nothing runs at file load. Conventional slot, after `modules/Frame.lua`: `core/DebugLogSetup.lua`'s `diagnostics` callback reads `NS.Diagnostics` at **run** time, and every read inside a section happens at call time. See [debug.md](./debug.md).

Carries the `COMMANDS` table (positional triples, published as `WhatGroup.COMMANDS` so the landing page renders the same data), the host verbs (`show`, `test`, `config`, `enable`, `disable`, `resetall`, `debug`) plus `WhatGroup:OpenSettings`, the `config` body the launcher's left click also reaches (and its right click, only where the client has no `MenuUtil`), the `parse` adapter that keeps `toggle` working, and `WhatGroup:OnSlashCommand`. ### The file header

Every source file starts with the same two-vararg header — `NS` is the addon's
private namespace, shared across files (WG-01). There is **no `_G.WhatGroup`**.
The first vararg is the addon's **folder** name, and it is spelled
`local addonName, NS = ...` in the eight files that read it (`core/CoreSetup.lua`,
`core/EnvSetup.lua`, `core/MediaSetup.lua`, `core/DebugLogSetup.lua`,
`core/LauncherSetup.lua`, `core/LifecycleSetup.lua`, `core/WhatGroup.lua`,

### Lifecycle

- **`OnInitialize`** (fires on `ADDON_LOADED` for `"WhatGroup"`, after every TOC line has executed): `defaults = Settings.BuildDefaults()` → `db = AceDB:New("WhatGroupDB", defaults, true)` → `self:RunMigrations()` → register `/wg` and `/whatgroup` chat commands. Debug state is session-only (`NS.State.debug`), **not** seeded from SavedVariables.
- **`OnEnable`** registers `GROUP_ROSTER_UPDATE`, `LFG_LIST_APPLICATION_STATUS_UPDATED` and the `PLAYER_REGEN_DISABLED` / `PLAYER_REGEN_ENABLED` pair that re-asks the `visibility` gate on a combat transition, snapshots `wasInGroup = IsInGroup()`, registers the Settings panel so the AddOns entry appears at login, and calls `NS.Launcher:Register()` — here rather than at file load because the table LibDBIcon keeps the button's position in is `db.global.minimap`, which `OnInitialize` has just built; the library's `Register` is idempotent. **No hook installation** here — hooks are at file-load (above). The popup's secure teleport button + `UISpecialFrames` insert (the real boot-taint sources) stay deferred to first `ShowFrame()`, and the reset popup registers lazily on first reset request — so GameMenu's `InitButtons` still runs in a clean context and Logout works correctly even after `/reload`.

`Settings.Register()` runs at `OnEnable` (and again as a no-op from `runConfig`). It defers the AceGUI body build to the parent and General subcategory's first `OnShow` (each behind its own one-shot guard). See [docs/settings-panel.md](./settings-panel.md#lazy-panel-build).

## Embedded libraries

Vendored under `libs/`. Order in `WhatGroup.toc` is dependency order:

1. `LibStub` — every Ace3 module's bootstrap.
2. `CallbackHandler-1.0` — needed by AceEvent.
3. `AceAddon-3.0` — `NewAddon`, `OnInitialize` / `OnEnable` lifecycle.
4. `AceEvent-3.0` — `RegisterEvent`, event handler dispatch.
5. `AceConsole-3.0` — `RegisterChatCommand`.
6. `AceTimer-3.0` — `ScheduleTimer` / `CancelTimer`; backs the one-shot notify delay (WG-17).
7. `AceDB-3.0` — `WhatGroupDB` storage.
8. `AceGUI-3.0` (loaded via its `.xml`) — checkbox / slider / button / heading widgets used by the settings panel.
9. `LibDataBroker-1.1` and `LibDBIcon-1.0` — the launcher's two libraries (launcher-§1), copied whole from Ka0s Bank Ledger. `LibKa0s-Launcher-1.0` resolves both with `LibStub(..., true)` at `Register` time, so neither is a hard dependency and a host with neither gets a launcher that reports itself absent.
10. `LibSharedMedia-3.0` (loaded via its `lib.xml`) — media registry; `core/MediaSetup.lua` calls `Media.RegisterLSM(addonName)` at load, which registers the library's JetBrains Mono (and its bar textures) so the debug console can render monospace and a profile can store a face by **name** rather than by a path naming one addon's folder.
11. `LibKa0s` (loaded via its `LibKa0s.xml`, **last**) — the shared Ka0s library. It loads the files `libs/LibKa0s/LibKa0s.xml` lists, in that file's dependency order (`Core.lua` first); the XML is the list, so it is not copied here. This addon takes ten of its majors — `LibKa0s-Core-1.0`, `LibKa0s-Env-1.0`, `LibKa0s-Compat-1.0`, `LibKa0s-Lifecycle-1.0`, `LibKa0s-Media-1.0`, `LibKa0s-DebugLog-1.0`, `LibKa0s-Launcher-1.0`, `LibKa0s-Options-1.0`, `LibKa0s-Schema-1.0` and `LibKa0s-Slash-1.0` — one wiring file each (`core/CoreSetup.lua`, `core/EnvSetup.lua`, `core/Compat.lua`, `core/LifecycleSetup.lua`, `core/MediaSetup.lua`, `core/DebugLogSetup.lua`, `core/LauncherSetup.lua`, `settings/OptionsSetup.lua`, `settings/SchemaSetup.lua`, `settings/Slash.lua`). `LibKa0s-Perf-1.0` is **declined** on structural grounds: there is no hot path to measure (zero `OnUpdate` handlers; the addon's one repeating timer is the popup-bounded teleport countdown at `modules/Frame.lua:524`, which ended the no-combat-path exemption on 2026-08-06 without giving Perf anything to bracket), and `suspend` would stop a *capture* addon capturing, so a measurement window would cost the player the group info they joined for. The folder is still vendored whole and both Perf files still load — whole-folder vendoring, anti-patterns #48; what is declined is the wiring. See [`LIBKA0S-15`](https://github.com/tusharsaxena/WhatGroup/issues/7).

`AceHook-3.0` was previously vendored (for `SecureHook` / `RawHook`), but both have been replaced with direct Blizzard `hooksecurefunc` calls — AceHook's wrappers leave per-invocation closures that taint Blizzard's secure-execute chain on Logout. The library directory has been removed from `libs/`.

Libs are copied as-is from Ka0s KickCD (`/mnt/d/Profile/Users/Tushar/Documents/GIT/KickCD/libs/`) so versions stay aligned across the user's addons — except `LibSharedMedia-3.0`, copied from Ka0s AbsorbTracker, and `LibKa0s`, vendored whole from the sibling repo `../LibKa0s` — which is also where the JetBrains Mono face and the icon catalog now live, under `libs/LibKa0s/media/`. Refresh by re-copying those directories.

## media/

- `logos/`, `screenshots/` — logo / screenshot assets referenced by `README.md` and the Settings landing page. Not loaded by Lua directly (both logos are referenced by texture path). Two logo files ship (layout-§4): `whatgroup.logo.tga`, drawn at 300×300 on the landing page, and `whatgroup.logo.128.tga` — 128×128, uncompressed 32-bit, regenerated from the `.png` source by layout-§4's recipe — which is the TOC's `IconTexture`, the minimap button's icon and the broker object's icon at once.
